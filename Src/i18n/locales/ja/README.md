## 要出貨日文，三步

1. 把剩下的空字串填滿
   - 具名參數 `{proEarly}` / `{cards}` / `{varToken}` **一個都不能少**，
     少了那個數字會無聲消失（check-i18n 會擋下來）
2. `scripts/check-i18n.mjs` 的 `SKELETON` 集合移除 `'ja'`
3. `nuxt.config.ts` 的 `i18n.locales` 加一筆：

   ```ts
   {
     code: 'ja',
     language: 'ja',
     name: '日本語',
     files: ['ja/common.json', 'ja/home.json', /* …其餘 8 個 */],
   }
   ```

三步缺一，建置會失敗並指出缺哪一步。

### 🔴 第 2 步現在會失敗 —— 這是刻意的

`SKELETON` 一旦移除 `'ja'`，空字串就從「允許」變成「建置失敗」，
而 `what-we-dont-do.json` 那 36 個 key 是空的。所以出貨日文之前，
**那一頁的去留必須先有結論**：要嘛翻完，要嘛連同路由一起砍掉。
卡在「路由還在、沒有入口」的狀態下出貨，只會多生一個
`/ja/what-we-dont-do` 孤兒頁。

## 出貨前還要處理的兩件事

- **誠實紅線由誰覆核。** check-i18n 只驗 key 齊不齊、`{...}` 參數在不在，
  **不驗這句日文講的是不是真的**。日文是一整個新的對外主張表面，
  上線前需要一個讀得懂日文的人對照
  [`Docs/webspec/主張與依據.md`](../../../../Docs/webspec/主張與依據.md) 走一遍。
- **`fallbackLocale` 的取捨還沒裁決**（見
  [`Docs/webplan/效能待改清單.md`](../../../../Docs/webplan/效能待改清單.md) E5）。
  維持現狀的話，漏 key 會**無聲退回中文**而不是報錯 —— 而拿掉 `SKELETON`
  豁免的那一次，正是最容易漏 key 的一次。
