## 1. 功能名稱：把 canonical 收回自己的網址

**問題 / 運用機會**

### 1-1　實測到的事實（2026-09-11 查核，非推論）

正式部署 `https://promptbox-web.vercel.app` 的原始 HTML，**每一頁**都輸出：

```
首頁      <link id="i18n-can" rel="canonical" href="https://promptbox.app">
          <meta property="og:url" content="https://promptbox.app">
/pricing  canonical → https://promptbox.app/pricing
/download canonical → https://promptbox.app/download
```

**不只 canonical，hreflang 四條全部指過去，包含 `x-default`**：

```
href="https://promptbox.app"      hreflang="x-default"
href="https://promptbox.app"      hreflang="zh"
href="https://promptbox.app"      hreflang="zh-Hant"
href="https://promptbox.app/en"   hreflang="en"
```

`x-default` 的語意是「不管讀者哪國人，預設送去這裡」。
**canonical ＋ x-default ＋ og:url 三者同時指向同一個外部網域，是能給搜尋引擎的最強「正本在別處」訊號，沒有更強的組合。**

`https://promptbox-web.vercel.app/robots.txt` 回 **404** —— 沒有任何東西擋爬蟲。

### 1-2　`promptbox.app` 上面實際是什麼

| 項目 | 實際值 |
| --- | --- |
| 標題 | `Home — PromptBox` |
| 標語 | Streamlined Communication for Iterating Fast |
| 產品 | 自架式團隊聊天／看板／檔案共享 |
| 按鈕 | Log In、Get Started Today |
| 頁尾 | `@2024 Acme Corp. All rights reserved.` |

一個沒改過的行銷樣板站。**這個網域不是我們的** —— [待討論問題 Q10-a](../webplan/待討論問題.md) 白紙黑字「**仍未購買**」。

> 📌 **附帶情報（與改名有關）**：那個站的 `<title>` 是 **`Home — PromptBox`**，正文卻是原封不動的 Acme 樣板。
> 也就是說**已經有人拿 PromptBox 這個名字佔住 `.app`**。
> 產品正因商標問題規劃改名（[待討論問題 §八](../webplan/待討論問題.md)），這條算是額外佐證，
> 也代表**就算哪天決定買，`promptbox.app` 也已經買不到了**。

### 1-3　三個後果

| # | 後果 | 嚴重度 |
| --- | --- | --- |
| 1 | **搜尋引擎把樣板站當正本。** 真網站可能不被收錄，或被判為重複內容 | 高 |
| 2 | **分享預覽抓錯。** `og:url` 指向他站，社群平台可能顯示對方的標題／縮圖 | 中 |
| 3 | **使用者手打 `promptbox.app` 落在別人的註冊頁。** 對一個保管 API key 的產品，畫面上有 Log In／Get Started ⇒ 觀感接近釣魚 | 中（見下） |

> ⚠️ **後果 3 的急迫性要講精確**：目前主要流向其實是**反過來**的 —— App v3.9.0 的
> 設定頁「官方網站」按鈕會把人正確送到 Vercel 站，問題出在**到站之後爬蟲被告知正本在別處**。
> 真正大量手打 `promptbox.app` 的情境，要等對外文案印出那個網域才會發生（現在還沒有）。
> 所以急迫性排序是 **① 收錄 ＞ ② 分享預覽 ＞ ③ 手打網址**。

### 1-4　🔴 這不是沒人發現，是「防護假設過期了」

[NewName.md §4-2](../webplan/NewName.md) 早就寫過這個風險：

> 但**不要放著不改** —— 本機 dev 與任何忘了設變數的環境，會靜默用舊網域產出 canonical／hreflang／og:url。

當時判定「可以先擺著」，靠的是 [待討論問題 Q10-a](../webplan/待討論問題.md) 這句：

> 目前**完全沒有任何網址被索引**，這個乾淨的起點不該浪費掉。

**這句話現在不成立了。** 在它（2026-08-27）之後發生三件事：

1. Vercel 正式部署已在線上，且**沒有 robots.txt**
2. App **v3.9.0** 起設定頁「官方網站」按鈕由 disabled 改為可用，撞配額的升級按鈕也改指本站（[App事實依據 V390-1](../appsync/App事實依據.md)）—— 真的有使用者被導過來
3. 導過來之後，每一頁都在跟爬蟲說「正本在 promptbox.app」

**那個被小心保護的「乾淨起點」，正在被主動送給 `promptbox.app`。**

### 1-5　🔴 兩個決策被混在一起了

這是整份 WL 最關鍵的一點：

| | 決策 | 狀態 |
| --- | --- | --- |
| **A** | 改名前不要買網域 | ✅ **這個判斷沒問題，應該維持** |
| **B** | canonical 指向一個不屬於我們的網域 | ❌ **從來沒有人真的決定過，它是 A 的副作用** |

**A 完全不需要 B。** 把 B 修掉不會動到 A 一根寒毛。

## 2. Proposed Solution

分成「一定要做的」和「要先決定的」兩塊。

### 2-1　一定要做：把網址基準指回自己（一行程式都不用改）

在 **Vercel 環境變數**加一條：

```
NUXT_PUBLIC_SITE_URL=https://promptbox-web.vercel.app
```

`i18n.baseUrl` 本來就吃它（[`nuxt.config.ts:75`](../../Src/nuxt.config.ts)），
canonical／hreflang／og:url 三者會**一起**跟著走。架構本來就是為此設計的 ——
買到真網域那天再改同一個變數即可。

同時把 fallback 也改掉，否則本機 dev 與任何忘了設變數的環境會繼續靜默產出舊值：

| # | 位置 | 現值 | 動作 |
| --- | --- | --- | --- |
| 1 | Vercel 環境變數 | 未設 | **設成 vercel.app 網址**（真正生效的那一處） |
| 2 | [`nuxt.config.ts:75`](../../Src/nuxt.config.ts) `i18n.baseUrl` | `'https://promptbox.app'` | fallback 換成 vercel.app 網址 |
| 3 | [`nuxt.config.ts:100`](../../Src/nuxt.config.ts) `public.siteUrl` | `'https://promptbox.app'` | ⚠️ **全專案零引用**（`app/`／`server/`／`scripts/`／`content/`／`i18n/` 都 grep 過）。**建議直接刪掉**，留著只會讓下次的人以為改了它有用 |

> 🔴 **這不違反 [CLAUDE.md](../../CLAUDE.md)「不要為了先接起來填假的環境變數」那條紅線 —— 理由要講清楚。**
>
> 那條紅線的**前提**是「四個變數留空時對應功能會**安全停用**」。實際查核：
>
> | 變數 | 留空的行為 | 安全？ |
> | --- | --- | --- |
> | `NUXT_PUBLIC_GTAG_ID` | 完全不載入 gtag，隱私頁自動改口 | ✅ |
> | `NUXT_PUBLIC_CONTACT_EMAIL` | mailto 改導訂閱表單 | ✅ |
> | `NUXT_BUTTONDOWN_API_KEY` | `/api/subscribe` 回 501，表單顯示未啟用 | ✅ |
> | **`NUXT_PUBLIC_SITE_URL`** | **退回一個第三方持有的線上網域** | ❌ **不安全** |
>
> **`NUXT_PUBLIC_SITE_URL` 是四個裡唯一「留空不會安全停用」的那一個。**
> 而且填 vercel.app **不是填假值 —— 網站真的就在那個網址上**，那是目前唯一真實的對外網址。

### 2-2　要先決定：vercel.app 要不要被索引

修好 canonical 之後會冒出一個新問題：**vercel.app 的網址開始累積收錄，等真網域到位就要處理 301** ——
這正是 Q10-a 當初想避開的事。兩個選項：

| | 做法 | 好處 | 代價 |
| --- | --- | --- | --- |
| **A** | 只修 canonical，讓 vercel.app 正常被索引 | 比賽曝光期搜得到 | 買真網域後要做一批 301，Q10-a 的「乾淨起點」失守 |
| **B**（建議） | 修 canonical **＋** 加 `robots.txt`（`Disallow: /`）或全站 `noindex` | **同時保住兩件事**：不再把權重送給他站，也維持「零收錄」的乾淨起點 | 搜尋引擎搜不到（但比賽期的流量本來就來自 App 按鈕與比賽頁，不是 Google） |

> ✅ **B 不是折衷，是真的把 Q10-a 的原意完整保住** —— 它想保護的是「沒有網址被索引」，
> 而 `Disallow` 正是直接達成那件事，比「指向一個別人的網域」可靠得多。
>
> ⚠️ **但 B 不能取代 2-1。** `robots.txt` 管不到 `og:url` —— **分享預覽（後果 2）只有修 canonical 才會好**。
> 兩件事要一起做，不是二選一。
>
> ⚠️ 技術細節：`Disallow` 只擋抓取，不保證已被外部連結指到的頁面不出現在索引裡。
> 若要「保證不收錄」，正確做法是**允許抓取 + `noindex` meta**。要哪一種請一併裁決。

### 2-3　真網域到位之後（等 P6，不在本 WL 範圍）

改同一個環境變數即可。同時要處理的連動項見
[上線前置鏈 P6／P7](../webplan/上線前置鏈.md) 與 [NewName.md §4-3](../webplan/NewName.md)（憑證 `iss`，過了就回不去）。

## 3. Potential Value（Priority 代表策略重要性，非開發順序）

- **對使用者**：手打或誤連時不會落在一個陌生的 Log In／Get Started 頁面。對一個賣點是「你的 API key 留在自己機器上」的產品，這一項不是體驗問題，是**信任問題**。
- **對產品成長**：保住改名／買網域之後的 SEO 起跑點。現在每多一天，就多一點權重被歸給他站。
- **可能的指標改善**：不是「改善」，是**止血** —— 讓後續所有 SEO 投入不會流到別人家。
- **成本極低**：主要修法是**一個環境變數**，不需要改任何 `.vue`，不需要重寫任何文案。

---

## 4. Priority

**High** ——「策略重要性高 × 成本極低」。

不是因為它今天就在大量流血（目前收錄量應該還很小），
而是因為**它每天都在累積、而修它只要幾分鐘**。這種比例的項目沒有理由排在後面。

> 唯一真正需要人決定的只有 §2-2 那一題（要不要讓 vercel.app 被索引）。
> §2-1 沒有任何待決事項，**可以立刻做**。

### 5-3　驗證方式（改完一定要跑）

不要只看本機建置，**要打線上**：

```bash
curl -sS -L https://promptbox-web.vercel.app/ \
  | grep -o '<link[^>]*canonical[^>]*>\|property="og:url" content="[^"]*"\|hreflang="[^"]*"'
```

四條 hreflang（含 `x-default`）、canonical、og:url **六個都要指向自己**才算修好。
`/pricing`、`/download` 各再驗一次。

> ⚠️ **本機 `.output/` 綠不代表線上綠。** 真正生效的是 **Vercel 的環境變數**，
> 本機建置吃的是 `Src/.env`（目前為空）。
> 這與「`check:docs` 掃工作區不掃提交樹」是同一類陷阱 —— **驗錯了對象**。

### 5-4　風險與未知

- ⚠️ **不知道目前已被收錄多少。** 修之前建議先用 `site:promptbox-web.vercel.app` 查一次當基準線，修完再查一次確認方向對。
- ⚠️ **`promptbox.app` 的所有權會不會變**不在我們控制內。對方今天是樣板站，明天可能變成任何東西 —— 這正是「不要把 canonical 指向不屬於你的網域」的根本理由，**與那個站現在長什麼樣無關**。
- ⚠️ **與 P6 的順序**：本 WL **不應該**等 P6。它是 P6 之前的止血，不是 P6 的一部分。把它綁進 P6 等於讓它繼續躺著。
