## 1. 這個資料夾是什麼

`Docs/Wishlist/` 收**可能**要做的功能——尚未決定，也還沒排版本。

| 資料夾                                        | 語意                                              |
| --------------------------------------------- | ------------------------------------------------- |
| **`Docs/Wishlist/`**                           | **可能**要做（尚未決定）← 本資料夾                |
| [`Docs/refer/BRD/`](../refer/BRD/BRD-00_索引與決策狀態.md) | 商業決策。**WL 的方向若與 BRD 衝突，一律 BRD 勝** |

> 🔴 **`refer/` 的副本預設不適用於 `refer/BRD/`。** [文件規則 §7](../文件規則.md) 給 `refer/` 的預設是
> 「⚠️ 副本，可能已過期」，但 **`Docs/refer/BRD/` 六冊是 BRD 正本**（2026-08-30 創辦人確認，見
> [CLAUDE.md](../../CLAUDE.md) 紅線 3）。改配額、價格、Free／Pro 邊界時以它為準。

> **WL 是所有文件類型裡最容易腐化的**（App repo 的經驗）：它們數量最多、生命週期最長（有的躺了 5 個月）、
> 而且**過去沒有任何流程會強迫回頭更新**——功能出貨了，不會有人記得回來把 WL 標成完成。

## 2. 資料夾語意 → 統一詞彙的翻譯

### 2.1 為什麼資料夾不夠用

本資料夾原本用**位置**表達狀態：根層＝待辦、`DONE/`＝做完、`WONTFIX/`＝不做。問題是——

> **`DONE/` 和 `WONTFIX/` 根本不在同一個軸上。**
>
> - `DONE/` 講的是**實作進度**（蓋完了）
> - `WONTFIX/` 講的是**方向有效性**（這條路不走了）
>
> 一個檔案只能放在一個資料夾，所以**兩個軸只能表達一個**。

### 2.2 翻譯規則

| 檔案位置            | 預設方向有效性              | 預設實作進度         |
| ------------------- | --------------------------- | -------------------- |
| `Wishlist/` 根層    | ✅ **現行**（待評估／待做） | 未動工               |
| `Wishlist/DONE/`    | ✅ **現行**                 | ✅ **已出貨 vX.X**   |
| `Wishlist/WONTFIX/` | 🚫 **主動放棄**             | 未動工（且不會動工） |

**檔頭標記可覆寫預設值。** 只有在「與資料夾預設不符」時才需要寫檔頭——
放在根層的 ✅ 現行項目不必逐一標註，省去 22 份樣板噪音。

完整詞彙定義見 [`Docs/文件規則.md` §4（狀態詞彙）與 §7（資料夾預設值）](../文件規則.md)。

## 6. 要新增一份怎麼做

1. 複製 [000.通用Wishlist模板](000.通用Wishlist模板.md)，檔名 `[流水號].WL_[簡略描述].md`，流水號接續本表最大值。
2. 填完八欄基本資料 + 五節內容，**條列式，不寫長段落**。
3. **回來更新 §3 這張表** —— 沒進表的 WL 等於不存在。
4. 檔名裡不要出現 `vX.X`：官網沒有版本號，那是 App repo 的體例（[文件規則 §8](../文件規則.md)）。

> 🔴 **WL 不能取代 `webplan/`。** App repo 的 WL 掛在「發一次 binary」這根軸上，
> 官網沒有那根軸（[文件規則 §1](../文件規則.md)）。所以這裡的 WL 只回答「這個想法還算不算數」；
> **真的要動手時，該開檔的仍然要去 `webplan/` 開** —— 新增路由、新增 server route、
> 接新的外部服務、新增環境變數，這四件事一律必開。WL-003（新路由 `/about`）與
> WL-004 若走 `/demo` 路線，都落在這條規則裡。
