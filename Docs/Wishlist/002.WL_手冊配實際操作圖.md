## 1. 功能名稱：使用手冊配實際操作圖

**問題 / 運用機會**

- 現況：[Src/content/docs/](../../Src/content/docs/) 九章手冊**一張圖都沒有** —— grep 過全部 markdown，零個圖片引用。
- 素材早就備好了：[Docs/refer/promptbox-spare-img/unused-assets/](../refer/promptbox-spare-img/unused-assets/) 躺著 9 張產品截圖（`card-editor`、`consent-approve`、`consent-denied`、`lock`、`release-audit`、`tray-status`、`index`、`index-dark`、`Video`）。
- **這不是新想法，是階段二留了料沒做完。** [PRD 階段二 §FR-15](../webplan/PRD_階段二_Content化.md) 明文保留它們，理由寫著：「正是本階段 docs 內容化最可能要用到的素材。刪掉它們是把素材當垃圾。」
- 第 5 章（機密卡授權窗）、第 8 章（設定與托盤）、釋放稽核是全手冊最抽象的三段，而它們**正好都有現成截圖**。

## 2. Proposed Solution

- 把需要的幾張從 `unused-assets/` 移進 `Src/public/assets/ExImg/`（現有三張內容圖也在那）。
- 章節對應（初步）：
  - `2.basics.md` → `card-editor`
  - `5.secrets.md` → `consent-approve` + `consent-denied` + `lock`
  - `6.chaining.md` → 已有 `chaining-demo.webp`
  - `7.mcp.md` → 已有 `MCP.webp`
  - `8.settings.md` → `tray-status`
  - 釋放稽核段落 → `release-audit`
- 沿用既有內嵌截圖樣式（[systemV2](../webspec/systemV2.md) 的 `rounded-[12px]`）與 lazy loading（階段二 FR-16）。
- 每張圖配一句說明，講清楚它示範的是哪個行為 —— 圖不是裝飾，是那一段文字的證據。

## 3. Potential Value（Priority 代表策略重要性，非開發順序）

- **對使用者**：五／八章與稽核段落純文字最難想像，配圖直接降低「裝了之後找不到功能」的摩擦。
- **對產品成長**：[BRD-01 §第二圈｜擴散器](../refer/BRD/BRD-01_定位與市場.md) 的打法就是「做好文件與模板，讓他們替你寫教學」—— 沒有圖的手冊很難被轉貼。
- **可能的指標改善**：下載後的啟用率、減少「這功能長什麼樣」的來信。

## 4. Priority

**High** —— 三件裡最先做的一件。素材現成、風險最低，而且是已規劃未完成的欠項。

## 5. Implementation Notes

- 🔴 **先決問題：手冊正文只有中文。** `docs.json` 三語系齊全，但那只是頁面外殼（標題、側欄）；正文（`2.basics.md` 等）是 zh-TW 單語，截圖也會是中文 UI。動手前要先決定：**只服務中文讀者**，還是連帶處理手冊翻譯（那是完全不同量級的工）。
  - 選前者 ⇒ 不必開檔，直接做（[文件規則 §1](../文件規則.md)）。
  - 選後者 ⇒ 那是要「先決定」的事，該在 `webplan/` 開一份。注意手冊正文是 `content/` 的 markdown，**不走 i18n 骨架那套**（`ja` 骨架只涵蓋 10 個 locale json，不含手冊正文）。
- 🔴 **截圖是一種對外主張。** 圖裡顯示的 UI 行為若與 v3.7.1 不符，等於一句沒有依據的話上線了。[主張與依據](../webspec/主張與依據.md) 目前只管文字，**三支護欄沒有一支會比對截圖與 App 版本**。建議補一列記下截圖對應的 App 版本，並在圖旁標註。
- 圖片重量：[效能待改清單](../webplan/效能待改清單.md) 已列 `chaining-demo` 需壓縮；新加的圖沿用同一標準（webp、寬度上限 1200）。
- 回寫義務：若在 `/docs` 新增區塊或改變連結去向，才需要動 [PageDescription/04_docs.md](../webspec/PageDescription/04_docs.md)；純插圖不改拓樸。
