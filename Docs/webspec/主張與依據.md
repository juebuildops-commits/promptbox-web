# 主張與依據（Claims & Evidence）

> **用途**：官網上每一句**對外主張**，配一條**可查證的依據**與**目前狀態**。
> **建立**：2026-08-28　·　**最後查核**：2026-08-30
> **為什麼需要它**：F11（「開源發布於 GitHub Releases」）、「也提供 macOS 版」、
> 「校驗碼供您核對**來源**」、「提供企業發票」—— 這四個問題全部是**事後一個一個撞出來的**，
> 而且是同一種失效模式：**頁面上有一句話，而它的依據不成立或已過期**。這張表把那件事變成可檢查的。
>
> **上位原則**：誠實紅線 C1 / C2 —— 誠實是紅線，不是美德。
> 「不得在任何介面或文案暗示超出實際的保護」「已知邊界必須明列，不得模糊」。
> 全文見 [App 事實依據 §二](../appsync/App事實依據.md)。

## 怎麼用

- **改文案之前**：先看這裡有沒有對應的列。沒有 ⇒ 你正在新增一條沒有依據的主張。
- **依據欄的三種寫法**，不可混用：
  - **連結** —— 依據就在這個 repo，點得開
  - **`App A5` 這種編號** —— 依據是 App 的行為，正本在 App repo，本 repo 只有 [App 事實依據](../appsync/App事實依據.md) 的快照
  - **「無」** —— **真的沒有依據**。不要為了讓表格好看而編一個連結出來
- **不必一次填完**。[PageDescription](./PageDescription/) 的「核心內容映射」是主張的來源清單，邊改邊補即可。
