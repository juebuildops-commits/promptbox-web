# 隱私權政策頁（`/privacy`、`/en/privacy`）

> 來源：`Src/app/pages/privacy.vue`、`Src/i18n/locales/{zh-TW,en}/privacy.json`、`Src/app/composables/useAnalyticsConsent.ts`、`Src/app/plugins/analytics.client.ts`

## 1. 頁面類型定義 (Page Typology)

### 【事實提取】

- 承載**單一長篇政策文本**，切分為七個編號主題段落，附最後更新日期（2026-08-27）。
- 含 **1 張第三方處理者矩陣**（3 個服務 × 3 個欄位：服務名稱、用途、可見資料）。
- 含 **1 個具實際效力的偏好設定控制項**——分析退出開關。該開關並非說明性圖示，其狀態寫入使用者瀏覽器的本機儲存，並決定分析程式碼是否被載入。
- 開關具**條件式存在性**：若站台未設定分析工具識別碼，整個開關不呈現，改以「本站目前未設定任何分析工具」的聲明取代；處理者矩陣中的對應列亦一併移除。
- 含 **1 個條件式資料收集表單**：未設定對外信箱時，聯絡段落以諮詢表單取代 `mailto:` 連結。
- 文本結構的首要段落並非收集項目，而是**適用範圍的切割**：宣告 App 與網站為兩件事，本政策不適用於 App。
- 含一組**否定式清單**（我們沒有的東西）與一組**權利清單**。

### 【推論分類】

**政策節點頁（Policy Node）兼功能應用頁（Utility）**。

此複合性質是本頁與典型隱私政策的關鍵差異。一般政策頁為純敘述性文本，其中對退出方式的說明會指向他處（第三方選擇退出工具、瀏覽器設定、或一封申請信）。本頁則將控制項**內嵌於敘述該項收集的段落之中**——文字說明與其對應的行使手段位於同一位置。因此本頁在系統中不僅是法遵文件，也是一個使用者偏好的設定入口。

## 2. 核心內容映射 (Content Ontology)

| 段落 | 承載的資訊實體 |
| --- | --- |
| **① 適用範圍切割** | 桌面應用程式自 v3.3.1 起完全不連網（無更新檢查、無遙測、字型隨程式打包）；因其不傳送任何資料，本政策**完全不適用於 App**；以下所有陳述僅涵蓋網站。附帶重申資料留存位置與加密方式（SQLCipher + 作業系統金鑰庫）。**2026-08-30 補述**：加上「唯一的網路元件是內建 MCP 伺服器，只監聽 `127.0.0.1`」—— BRD-03 §9 規則 5／6 要求講「完全不連網」時一併說明，主動說反而加分 |
| **② 收集項目 — 流量分析** | 收集範圍（頁面路徑、來源、概略地區、裝置類型、瀏覽器語言）；收集目的（決定後續內容方向）；四項收斂措施（IP 匿名化、關閉 Google Signals、關閉廣告個人化訊號、不投放廣告與再行銷）；退出機制的**性質聲明**——關閉後分析程式碼不被下載，而非設一個旗標令其不回報 |
| **③ 收集項目 — 電子報** | 收集條件（僅使用者主動填寫）；用途限定為兩項（新版通知、早鳥資格登記）；關閉開信追蹤像素的聲明；退訂機制與「不保留曾退訂名單」的補充 |
| **④ 否定清單** | 四項不存在的事物：無帳號系統、無廣告與跨站追蹤器、無操作錄影與熱區圖、不轉售或分享 email |
| **⑤ 瀏覽器儲存清單** | 兩個本機儲存鍵的完整列舉：`pb-theme`（主題偏好）、`pb-analytics`（分析退出狀態）；聲明不使用 cookie 做個人化或追蹤；聲明兩者永不送往伺服器 |
| **⑥ 第三方處理者矩陣** | Vercel（網站託管：伺服器日誌層級的 IP 與 User-Agent）；Google Analytics（流量分析：匿名化頁面瀏覽事件，可退出，條件式呈現）；Buttondown（電子報寄送：使用者主動提供的 email，不含開信追蹤） |
| **⑦ 使用者權利** | 三項：隨時在本頁退出分析、隨時從任一封信退訂、要求刪除 email 與相關紀錄 |
| **⑧ 聯絡管道** | 條件式：信箱位址或諮詢表單 |
| **⑨ 政策變更程序** | 實質變更將更新頁首日期並於電子報說明；聲明不擴大收集範圍 |
| **控制項實體** | 分析退出開關（含當前狀態的文字描述：開啟中／已關閉且程式碼不會載入） |

**本體特徵**：本頁的資訊實體有相當比例屬於**否定式與程序式**，而非典型政策頁的免責式。四項否定清單、兩個本機儲存鍵的窮舉、以及三項可行使的權利，皆為可被外部驗證的具體陳述——瀏覽器的開發者工具即可查核其中多數項目。這與以免責為目的的法律文本在本體結構上有本質差異。

- [語言切換] -> `/privacy` ⇄ `/en/privacy`

### 外部連結（External Outbound）

- [聯絡表單提交] -> `/api/subscribe` -> Buttondown 名單服務（伺服器端轉發）

## 4. 問題解決與意圖解析 (Problem Resolution & Intent)

### 【事實】

本頁提供：適用範圍的界定、兩類收集項目的範圍與目的說明、四項收斂措施、一份否定清單、本機儲存項目的完整列舉、第三方處理者的用途與可見資料、三項使用者權利、一個可立即行使的退出控制項，以及聯絡與變更程序。

### 【推論】

本頁預設的使用者動機與一般隱私政策頁有顯著差異。一般政策頁的訪客多為法遵查核者或爭議發生後的追溯者，其到訪率低且行為被動。而本站的核心銷售主張即為「我們不追蹤你」——這使本頁成為**該主張的驗證場所**。

因此可推論三種動機：①**主張驗證者**——被首頁的隱私論述說服至一定程度，前來查核該立場在網站自身是否一致；②**權利行使者**——已決定退出分析或退訂，前來尋找操作方式；③**法遵查核者**——標準的政策閱讀需求。

第一種動機的存在有結構證據：頁面首段處理的不是收集項目，而是「App 與網站是兩件事」這個**看似與政策無關的界定**。此段落只有在預設讀者是「來查核產品主張」而非「來閱讀法律條款」時才具備必要性。

### 【價值判斷】

本頁解決的核心問題，是一個由產品立場本身所製造的內在矛盾。

一個以「完全不連網、不追蹤」為賣點的產品，其官方網站在營運上必然需要流量分析與名單收集——**網站的行為與產品的主張表面上互相牴觸**。若不處理，一位認真的訪客在發現網站載入分析程式碼時，將合理推論該產品的隱私宣稱亦不可信。本頁以首段的範圍切割正面處理此矛盾：明確區分「不連網的是 App」與「有分析的是網站」，並將兩者的資料邊界分開陳述。這解決的是一個若被沉默對待就會反噬核心賣點的結構性風險。

其次，本頁將行銷承諾降落為**可執行與可查核的形式**。「我們不追蹤你」在首頁是一句主張；在本頁則被拆解為：可窮舉的本機儲存鍵（兩個）、可指名的第三方（三個）、可查核的收斂措施（四項）、以及一個可立即操作的開關。其中退出機制的性質聲明尤其關鍵——頁面明確區分了「載入後令其不回報」與「根本不載入」兩種業界做法，並宣稱採用後者。這是一項可由訪客在自己的瀏覽器中即時驗證的陳述，因而將信任問題從「是否相信廠商」轉為「是否願意查證」。

在整體業務流程中，本頁不參與轉換漏斗，但承擔**信任基礎的維護**職能：它是全站唯一一處，產品的核心主張被以可被否證的形式陳述出來的位置。
