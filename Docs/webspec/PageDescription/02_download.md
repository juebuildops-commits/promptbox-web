## 1. 頁面類型定義 (Page Typology)

### 【事實提取】

- 頁面承載**具體的檔案物件實體**：兩份可下載檔案，各自帶有檔名、版本號、體積與 SHA-256 雜湊值。
- 含**平台條件判斷**：依訪客作業系統改寫主要行動點的標籤、目的地與說明文字（Windows / macOS / 其他三分支）。
- 含**未上市狀態宣告**：macOS 版以旗標 `MAC_READY = false` 標記為「即將推出」，該平台無檔案實體，行動點轉為登記管道。
- 含**單一資料收集表單**（email，分類為 `updates`）。
- 含程序性內容：三步驟上手流程、**三則**安裝注意事項（2026-08-31 由四則減為三則）、兩條校驗指令。
- 含一則**主動的缺陷揭露**：說明安裝檔未經程式碼簽章、Windows 會顯示警告，並明言不要求使用者忽略該警告。

### 【推論分類】

**功能取得頁（Utility / Acquisition Page）**，位於轉換漏斗末端，同時兼具**發佈公告節點**的性質。

判定依據：頁面的存在目的是交付一個具體物件（安裝檔），而非傳遞理解。其資訊全部服務於單一動作的完成與驗證。兼具公告性質，是因為本站是安裝檔的唯一發佈管道（無 GitHub Releases），因此版本號、檔案雜湊與平台狀態在此具有權威來源地位，而非他處事實的複述。

## 3. 連結拓樸分析 (Link Topology)

### 外部連結（External Outbound）

- [主要下載按鈕（Windows / 其他系統訪客）] -> Cloudflare R2 物件儲存上的 `.exe` 安裝檔（直接檔案下載，非頁面節點）
- [「下載 Windows 版」] -> 同上 `.exe`
- [「免安裝便攜版（.zip）」] -> R2 上的 `.zip` 封存檔
- [訂閱表單提交] -> 站內端點 `/api/subscribe`，再由伺服器端轉發至 Buttondown 名單服務。**使用者端不直接連線第三方**，此為單向的伺服器對伺服器出站

> 結構事實：檔案託管於 `pub-*.r2.dev` 公用開發網域，與網站主網域分離。因此下載動作跨越了信任邊界——校驗碼由網站提供、檔案由物件儲存提供，兩者為不同來源。

### 內部路由（Internal Routing）

- [導覽列主要按鈕] -> 本頁錨點 `#platforms`（此頁的按鈕不導向他頁，改為頁內定位）
- [安裝注意事項「為什麼還沒有數位簽章」] -> `/docs#install-safety`（跨頁深層錨點，指向手冊第九章）
- [主導覽與頁尾] -> 全站五個節點頁（首頁／下載／定價／手冊／更新日誌／隱私權）
- [頁尾：聯絡我們] -> 條件式（`mailto:` 或 `/privacy#contact`）
- [語言切換] -> `/download` ⇄ `/en/download`

### 頁內錨點（In-page Fragment）

- [主要行動點（macOS 訪客）] -> `#subscribe`（表單區）
- [「macOS 版釋出時通知我」] -> `#subscribe`

> 拓樸特徵：**macOS 分支的所有路徑最終皆匯流至同一個表單節點**。頁面沒有為缺件平台提供死路——無檔案可交付時，動線被重新導向至名單登記，而非停止。

## 4. 問題解決與意圖解析 (Problem Resolution & Intent)

### 【事實】

本頁提供：可執行檔的取得位址、驗證檔案完整性所需的雜湊值與指令、系統需求規格、安裝後的預期行為說明、一則關於安全警告的成因揭露，以及一個新版通知的登記管道。

### 【推論】

到達本頁的使用者已完成決策，其動機不再是「要不要用」，而是三個執行層面的問題：**「我該拿哪一個檔案」「這個檔案是不是原版」「我的機器跑不跑得動」**。

頁面對作業系統的偵測、安裝版與便攜版的並列、以及校驗碼區塊的存在，分別對應這三個問題。而未簽章揭露條目的存在，指向第四個未言明但確實存在的動機：**使用者在安裝過程中遭遇警告後，會回到來源頁尋求解釋**——該條目與其指向的手冊章節，是為這個「安裝中斷後回訪」的時序而配置的。

### 【價值判斷】

本頁解決兩個結構性的資訊落差。

**其一，無簽章憑證所造成的來源信任缺口。** 作業系統的信任機制依賴憑證，而本產品目前不具備。頁面的處理方式並非迴避或淡化，而是明確承認該保證不存在，並提供一個**性質不同但可自行執行**的替代驗證（校驗碼證明完整性，不證明來源）。這在業務意義上是以「揭露的完整性」換取「憑證的權威性」——一個無法消除的缺口被轉換為一個可被理解的已知條件。

**其二，零連網產品無法自我告知新版的通道斷裂。** 產品自 v3.3.0 起移除所有對外連線，這使「有新版了」這個訊息在技術上無法從產品內部傳遞。本頁的表單即是這條被切斷的通道的外部重建——它把一個因隱私立場而產生的功能缺口，補回成一條使用者自願加入的推播管道。

此外，macOS 平台的缺件在此被轉換為需求登記而非流失。從漏斗角度看，本頁確保了「無法交付」不等於「動線終止」。
