## 1. 頁面類型定義 (Page Typology)

### 【事實提取】

- 頁面由 **9 份獨立的內容來源檔聚合而成**，但**共用單一路由**——所有章節位於同一個 URL 之下，不存在 `/docs/getting-started` 之類的子節點。
- 每個章節在資料結構上是具名實體，帶有：完整標題、導覽用短標籤、章節錨點識別、圖示鍵，以及可選的 Beta 標記。
- 章節順序由檔名前綴決定，導覽索引由內容集合自動推導而非人工維護——**目錄與內文為同一份事實的兩種投影**。
- 內容型態涵蓋：程序性步驟、語法規格與程式碼範例、概念對照表格、疑難排解問答、以及一份長篇的風險說明文。
- 兩個章節（卡片串聯、MCP 整合）帶 Beta 標記，構成頁內的功能成熟度分級。
- 非繁體中文語系下會呈現一則**內容語系落差聲明**：版面已翻譯、內文尚未，顯示原文而非隱藏或機器翻譯。
- 不含表單、不含資料收集。

### 【推論分類】

**節點頁（Node）／參考知識庫**，同時在結構上構成一個**單頁式聚合頁（Single-page Hub）**。

此雙重性質是本頁最顯著的結構特徵：它承載了通常會被拆為多個節點的知識量（9 個主題、涵蓋安裝到進階整合），卻在路由層維持單一節點。其後果是——外部若要指向特定主題，必須使用片段識別而非獨立網址（例如下載頁指向 `/docs#install-safety`）。因此本頁的定位是「**可被深層錨定的單體文件**」，而非可被分別索引的文件集合。

## 2. 核心內容映射 (Content Ontology)

九個章節即九個資訊實體：

| # | 章節 | 承載的資訊實體 |
| --- | --- | --- |
| 1 | 快速開始 | 安裝程序步驟；安裝版與便攜版的選擇條件；自訂安裝路徑 |
| 2 | 基本操作 | 卡片的建立與編輯欄位定義（標題、內容、說明、標籤、資料夾）；`#id` 編號的用途——作為 MCP 呼叫與串聯引用時的識別鍵 |
| 3 | 資料夾與標籤 | 兩套正交的組織機制：階層式資料夾分類、多選過濾式標籤；免費版與付費版在此皆無限制 |
| 4 | 變數樣板 | 語法規格 `{{變數}}`；動態替換的執行時機；一份提示詞適配多情境的重用模型 |
| 5 | 機密卡片與 AI 可見性 | **本手冊的核心概念定義**：「密碼保護」與「對 AI 可見性」被明確界定為兩條正交獨立的軸線；以對照表列出各組合下 AI 可取得的資訊範圍（名稱／說明／ID 可見，內容需人類授權才釋放）。**2026-08-30 新增一則邊界告示**：密碼保護的是卡片內容，卡片名稱、說明、變數名稱與變數預設值**不受密碼保護**（BRD-03 §9 規則 1／2／7；ADR-006）—— 原本全站沒有任何一處揭露這件事 |
| 6 | 卡片串聯（Beta） | 引用語法 `{{@prompt:N}}`；遞迴組合模型；串聯資料夾與專屬引用槽的概念 |
| 7 | MCP 整合（Beta） | 本機 MCP 伺服器規格（Streamable HTTP 與 SSE）；相容客戶端清單（Cursor、VS Code、Claude Desktop、Windsurf、Claude Code、Cline）；IDE 端的 JSON 設定範例與本機連線位址格式 |
| 8 | 設定與疑難排解 | 版本更新的取得方式（無自動檢查、email 通知、手動覆蓋安裝）；常見問題排查；意見回饋管道 |
| 9 | 安裝時的安全提示 | SmartScreen / Gatekeeper 警告的**成因說明**；未購買簽章憑證的原因（商標更名與公司登記的時序問題）；三條自行查證途徑；一則明確的能力邊界聲明——校驗碼證明完整性但不證明來源；以及對「買了憑證警告也不會立即消失」的補充說明 |

**本體結構上的特殊項**：第九章在內容性質上與其餘八章不同。前八章為操作指引（回答「怎麼做」），第九章為信任論證（回答「為什麼會這樣，以及你如何自行查核」）。它被收納於操作手冊之下，是因為它承接的是安裝流程中的一個中斷點。

## 4. 問題解決與意圖解析 (Problem Resolution & Intent)

### 【事實】

本頁提供：安裝與基本操作的程序指引、三組專有語法的規格定義（`{{變數}}`、`{{@prompt:N}}`、MCP 設定 JSON）、一組安全模型的概念界定、相容客戶端清單、疑難排解條目、意見回饋管道，以及一份針對安裝警告的成因說明與自行查證方法。

### 【推論】

本頁服務三種在時序上互不重疊的使用者動機：

1. **安裝中斷者**（尚未成為使用者）——在執行安裝檔時遭遇警告，循下載頁的連結到達第九章，動機是判斷「我是不是下載到了有問題的東西」。
2. **任務執行者**（已是使用者）——需完成某項具體設定（將 MCP 接上 IDE、撰寫變數樣板、鎖定一張機密卡），動機是取得語法規格與步驟。
3. **購買前查核者**（評估中）——以手冊作為功能真實性的驗證來源，動機是確認宣傳頁上的能力是否具備可操作的細節。

第三種動機在資訊架構上有間接證據：手冊完整公開、無需登入即可閱讀，且 Beta 標記被保留在公開文件中而非隱去——這使手冊同時具備規格書的效力。

### 【價值判斷】

本頁在業務流程中解決兩個性質不同的問題。

**其一，降低產品的認知門檻。** 本產品的差異化能力（機密可見性雙軸、卡片串聯、MCP 整合）皆為非直觀概念——它們沒有既有的心智模型可供類比，僅靠介面探索難以自行推導。第五章將「密碼保護」與「AI 可見性」形式化為兩條獨立軸線並以對照表窮舉組合，其作用是把一個容易被誤解為單一開關的機制，重建為可被正確推理的模型。這減少的不只是學習成本，更是**因誤解安全邊界而造成的實質風險**。

**其二，承擔信任修復的終點職能。** 第九章解決的是一個發生在轉換之後、卻可能導致轉換逆轉的斷點：使用者已下載檔案，卻在執行時被作業系統警告。此處的資訊落差是「作業系統說它無法辨識」與「這是否代表危險」之間的差距——兩者實際上並不等價，但一般使用者無從區分。該章節以承認缺口、解釋成因、並提供不依賴本方的查證途徑（第三方掃描服務）三個步驟填補此落差。其設計立場在文中被明確標示：不要求使用者忽略警告，因為該句型正是惡意軟體散布的典型話術。

綜合而言，本頁是全站唯一同時服務「安裝前查核」「安裝中斷」「安裝後使用」三個階段的節點，其資訊密度與涵蓋範圍反映了這個跨階段的定位。
