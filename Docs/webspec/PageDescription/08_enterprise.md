# 支持組織（`/enterprise`、`/en/enterprise`）

> 來源：`Src/app/pages/enterprise.vue`、`Src/i18n/locales/{zh-TW,en}/enterprise.json`、`Src/app/utils/pricing.ts`
> 建立：2026-08-31。依據：[主張與依據 §三](../主張與依據.md)「持有 25 席以上的組織，可列名為支持組織」那一列所掛的**產品待辦**
> 對標：`obsidian.md/enterprise`（形式），但**前提相反** —— 那頁是一萬多個組織的名單，本頁一個都還沒有

## 1. 頁面類型定義 (Page Typology)

### 【事實提取】

- 單一固定路由，無動態參數、無查詢字串狀態。
- 內容由五個具名區段構成：`hero`、`wall`（含 3 條否定式規則）、`license`（4 條 + 一則 notice）、`trust`（4 條）、`why`，末端為 `cta`。
- **含一個資料輸入欄位**：`SubscribeForm kind="commercial"`，且**僅在未設定 `NUXT_PUBLIC_CONTACT_EMAIL` 時出現**；有設定時該位置改為一顆 `mailto:` 按鈕（走 `useContact()`，與頁尾「聯絡我們」同一個機制）。
- 數值型事實全部以具名參數自 `app/utils/pricing.ts` 注入：`{sponsorSeats}`（列名門檻，2026-08-31 新增的常數）、`{commercial}`、`{commercialBundleTotal}`、`{commercialBundleSeats}`。
- 🔴 **本頁不在主導覽，也不在頁尾導覽。** 站內目前**沒有任何一條連結指向它** —— 它只能靠直接輸入網址或外部連結到達。這是刻意的，理由見 §4。
- 🔴 **因此它不會被 `crawlLinks` 爬到。** `nuxt.config.ts` 的 `nitro.prerender.routes` 已明列 `/enterprise` 與 `/en/enterprise` 兩條。**刪掉那兩條的症狀是建置成功、線上 404**（同 [根 README §五](../../../README.md) 描述的那個坑）。

### 【推論分類】

**意向登記頁（Intent Capture），但主體是一個「空狀態」。**

判定依據：頁面的核心資訊實體（支持組織名單）**目前是空的，而且會在可預見的未來持續是空的** —— 商業授權尚未開放購買（D3，定價頁那張卡的行動點是 disabled 的 `<button>`）。一般而言，內容為空的頁面不該上線；本頁成立的理由是**空狀態本身就是它要傳達的資訊**：它同時宣告了列名規則、以及「在收到第一筆授權費之前這裡不會有名字」這件事。

這使它與 [07_what-we-dont-do.md](07_what-we-dont-do.md) 屬於同一族：**兩頁都以「我們不會做什麼」構成主要內容**，差別在本頁多了一個未來會被填滿的容器。

## 2. 核心內容映射 (Content Ontology)

| 資訊實體 | 內容 |
| --- | --- |
| **列名規則** | 持有 `{sponsorSeats}`（＝25）席以上的商業授權即可列名。**唯一條件** —— 明文聲明沒有另外的贊助方案、沒有付費置頂、不分等級。<br>🔴 對標對象 Obsidian 用的是六層寶石分級（Diamond / Sapphire / …），**本站刻意不採用**：分級是一個沒有依據的新承諾，現有依據撐得住的只有「25 席以上可列名」這一句 |
| **空狀態聲明** | 「還沒有任何一家」＋為什麼選擇讓它空著。頁面上以 8 格 dashed 佔位框呈現（走 [systemV2 §3.3](../systemV2.md) 既有的佔位語彙），該格線標 `aria-hidden`，資訊全部在文字裡 —— **佔位格數不代表任何名額或預期數量** |
| **這面牆不會出現什麼**（否定式，3 條） | ①沒有實際付費的公司標誌（含使用中／測試中／洽談中）②案例研究與推薦語 —— 列名代表買了授權，**不代表背書** ③「受各大企業信賴」這類沒有數字可查的集合名詞 |
| **商業授權規格**（4 條） | ①功能與 Pro 完全相同 ②`${commercial}`／人／年，純年費、不提供買斷 ③買 4 席送 1 席（`${commercialBundleTotal}`／年 得 `{commercialBundleSeats}` 把 key）④榮譽制：App 端不檢查到期、無機器碼綁定、無密碼狗；到期後已安裝版本永久正常運作 |
| **未開放購買告示** | `notice-warning`。明言不接受任何購買意向、發票與報帳方式待公司登記完成後才公布。**與定價頁商業卡同一裁決（D3）**，兩處必須同進退 |
| **IT 與資安的四條**（皆為既有主張的複述，非新主張） | ①零主動外連 —— 🔴 **同句內含 MCP 只監聽 `127.0.0.1` 的本機 listener**（BRD-03 §9 規則 5／6，拆成兩條會讓第一條變成不完整的主張）②SQLCipher + DPAPI／Keychain，機密卡再一層 scrypt + AES-256-GCM，**同段揭露「卡片名稱／說明／變數名稱／變數預設值不受密碼保護」的邊界**（規則 1／2／7）③無伺服器、無帳號、無租戶，**並主動指出代價**：備份與裝置遺失由客戶自己的 IT 流程承擔 ④無 time-bomb（ADR-008 刻意不存在的欄位） |
| **收入結構論證** | 為什麼一個本地優先的工具需要企業付費：不賣資料／不投廣告／不做市集抽成（＝[07](07_what-we-dont-do.md) 的 `features.i5`）排除之後只剩一條收入線 |
| **元資料實體** | 標題與描述以「尚未開放購買」收尾 —— 搜尋結果直接顯示的那一句不得暗示現在買得到 |

本體特徵：**本頁承載的「未來承諾」密度是全站最高的**（列名、發票、買 4 送 1、開放時主動聯絡），而其中**沒有任何一項今天可以兌現**。這使它與 `/pricing` 同屬最容易在日後產生落差的頁面 —— 差別在定價頁有 `check:i18n` 守著數字，本頁的承諾**一條都沒有機器在守**。

- `POST /api/subscribe`（`kind: "commercial"`，tag 由伺服器決定）。全站第 6 個嵌入該表單的頁面。

## 4. 問題解決與意圖解析 (Problem Resolution & Intent)

### 【事實】

本頁不提供任何今天可執行的交易路徑。唯一的行動點是留下公司信箱（或寄信），且頁面自己明說現在不收錢。

### 【推論】

從「沒有任何入站連結卻仍然上線」可反推它服務的不是站內流量，而是**兩種站外情境**：其一，有人在公司裡想導入這個工具，需要一個可以貼進採購或資安審查信件的網址；其二，未來的支持組織需要看到列名規則長什麼樣，才能判斷買 25 席換不換得到他們要的東西。

**它刻意不進導覽**（創辦人 2026-08-31 裁示）：商業授權尚未開放購買，導覽裡多一個「支持組織」只會把一般訪客送到一個買不了東西的頁，而那正是 D3 決定把定價頁商業卡整張置灰時要避免的事。**沒有連結不等於沒上線** —— 它是一個「有人問起才給網址」的頁面。

### 【價值判斷】

本頁解決的是**空名單的呈現問題**。

一面空的支持者牆有三種處理方式：不做這頁、放上「使用中」的公司標誌把它填滿、或如實說它是空的。第二種在業界極為常見，而它的問題不是不道德，是**沒有資訊量** —— 讀者無法從那面牆判斷這個產品有沒有真的收到錢，也就無法判斷它會不會在兩年後消失，而那恰好是採購一個保管密鑰的工具時最該問的問題。本頁選第三種，並把「不會出現什麼」寫成三條，讓這面牆日後被填滿時**它的含義是明確的**。

⚠️ **本頁最容易被侵蝕的地方，與 [07](07_what-we-dont-do.md) 是同一種**：第一次有公司表達興趣時，`wall.never.i1`（不放沒付費的標誌）會立刻變成一句擋路的話。它沒有機器護欄，只有 `enterprise.vue` 的檔頭註解與本文件。

### 🔴 上線前仍待裁示的一件事

**列名同意怎麼取得，目前沒有裁示。** 頁面現在只承諾「持有 25 席以上可以列名」，沒有說列名是自動的還是需要對方同意 —— 這在文案上是安全的（沒有承諾任何事），但**放上第一個標誌之前必須先有答案**：使用公司名稱與商標需要對方授權，而「買了授權就自動被公開列名」對某些客戶是採購上的阻礙，不是好處。
這件事**不是文案問題，是流程問題**，應在商業授權開放購買前一併決定（與發票、報帳同一批）。在有裁示之前，不得在頁面上加任何描述列名流程的句子。
