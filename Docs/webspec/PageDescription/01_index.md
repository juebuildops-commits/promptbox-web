## 1. 頁面類型定義 (Page Typology)

### 【事實提取】

- 單一固定路由，無動態參數、無分頁、無查詢字串狀態。
- 內容由七個具名主題區段構成：產品命題陳述、信任屬性列（`trust`）、`privacy`、`advanced`、`price`、`faq`、結尾轉換召喚（`cta`）。
- 承載 **5 則問答條目**（`q1`–`a5`）與 **4 張商業方案摘要**（Free / Pro / Lifetime / Commercial）。
- **含一個資料輸入欄位**（2026-08-30 起）：結尾轉換召喚區內的 email 訂閱表單（`SubscribeForm`，`kind="updates"`），是本頁唯一會產生提交行為的實體，送往全站唯一的 server route `/api/subscribe`。此外頁內唯一的狀態切換是問答條目的展開。
  > **變更前的狀態**：本頁原本**不含任何輸入欄位**。訂閱表單只存在於 `download` / `pricing` / `changelog` / `privacy` 四頁，而 `/` 是曝光期流量的主要落點 —— 該缺口記錄於 [待討論問題 §D30](../../webplan/待討論問題.md) 末節。
- 所有數值型事實（價格、配額、名額、月數）並非寫死於文案，而是以具名參數自 `app/utils/pricing.ts` 的單一常數表注入，語系檔僅保留 `{proEarly}`、`{cards}` 等佔位符。
- 各主題區段對外部節點頁（下載、定價）皆為**摘要級複述**，不含該節點的完整事實集（例：價格卡不含規格對照表、不含促銷條款）。

### 【推論分類】

**到達頁（Landing Page）兼站內樞紐（Hub）**。

判定依據為兩項結構特徵：其一，頁面自身不是任何資訊的終點——每一個主題區段最終都指向另一個節點頁作為權威來源；其二，頁面同時聚合了原本分屬四個節點（下載、定價、手冊、隱私）的摘要，構成一個「全站命題的壓縮索引」。它承擔說服與分流兩種職能，而非資訊保存職能。

## 4. 問題解決與意圖解析 (Problem Resolution & Intent)

### 【事實】

本頁提供五類資訊節點與兩條行動路徑：①產品範疇定義；②安全機制與資料流向的機制性解釋；③三組進階能力的規格摘要；④四種授權的價格與權利邊界；⑤五則針對疑慮的問答。行動路徑為三條（2026-08-30 起）：「前往下載」、「前往定價」，以及**頁內完成的 email 訂閱**。仍無交易行為。訂閱表單是本頁唯一不需離開即可完成的轉換 —— 在金流未開通、且 macOS build 不存在的現況下，它是本頁對這兩類訪客唯一接得住的動作。

### 【推論】

從資訊配置的優先序可反推預設使用者模型：頁面把「資料不上雲」置於首要區段（`privacy` 早於 `advanced` 與 `price`），且問答條目的第一則與最後一則分別為「會不會被上傳」與「真的免費嗎」——這指向的動機並非「尋找一個提示詞管理工具」，而是「**已知有這類工具，但不信任雲端方案**」。

預設使用者為：具備 AI 工具日常使用經驗、已累積具價值的提示詞資產、對第三方託管抱持疑慮，且對付費軟體的長期可用性（是否會被鎖、是否被迫訂閱）敏感的個人使用者。其到訪動機為三段式驗證——「這是什麼」→「它會不會外洩我的東西」→「它要花我多少錢」——三者皆通過後才產生行動意圖。

### 【價值判斷】

本頁解決的核心問題是**不可觀察屬性的驗證困難**。

「本地儲存、不連網、加密」屬於使用者在安裝前無法自行查證的性質——與可截圖展示的功能不同，隱私承諾在購買決策點上是不可見的。本頁的處理方式是將抽象承諾拆解為可被指名的機制（SQLCipher、AES-256-GCM、OS Keychain、DPAPI、當次授權釋放），使一個原本只能被「相信」的主張，轉為可被外部知識查核的技術陳述。這消弭的是「宣稱隱私」與「實際架構」之間的資訊落差。

其次，本頁以免費配額的具體數字（45／3／5／2）取代模糊的「免費試用」，將試用門檻的不確定性一併移除——使用者在點擊下載前即已知道免費版的完整邊界，避免安裝後才發現受限所產生的信任損耗。

在整體業務流程中，本頁是漏斗的入口與分流器：它不完成任何轉換，而是將訪客依「即時價值需求」與「長期投資意願」分派至下載頁與定價頁。其成敗指標是分流率，而非轉換率。
