## 1. 頁面類型定義 (Page Typology)

### 【事實提取】

- 單一固定路由，無動態參數、無查詢字串狀態。
- **內容分屬兩個世界**：
  - **外殼**（`demo.vue`）—— `hero`、舞台容器、`disclaimer`、`cta`。走全站 layout，吃 i18n，受 `check:i18n` 管。
  - **本體**（`public/demo-app/index.html`）—— 1857 行、零外部依賴的單檔互動示範，內含自己的 design token、自己的圖示、自己的狀態機。**硬編碼繁體中文，三支護欄一支都不看它。**
- 兩者以**同源 iframe** 相接（`/demo-app/index.html?v=<DEMO_VERSION>`）。
- 🔴 **靜態檔放 `public/demo-app/` 而非 `public/demo/`**：後者會被服成 `/demo/index.html`，與本頁路由 `/demo` 共用前綴，誰贏取決於 Nitro 的目錄索引行為。改資料夾名讓衝突不存在。
- 🔴 **`?v=` 是必要的**：`public/` 底下沒有內容 hash。改了 demo 內容卻不換這個參數，回訪者拿到的是瀏覽器快取的舊版。
- **版面由 CSS 斷點決定（`lg:`），下載與否由 JS 決定**：`demoSrc` 初值為空字串 ⇒ SSR 與 hydration 首次渲染都不含 iframe，窄螢幕永遠不會被設值。**兩件事分開處理是刻意的** —— 只用 JS 判斷會讓預繪 HTML 永遠是手機分支，桌機訪客先看到「這個示範需要桌機寬度」再閃成 iframe；只用 CSS 隱藏則手機仍會下載那 80K。
- **iframe 高度 `min(78vh, 900px)`、下限 780px**（2026-09-05 自 720 上調）。🔴 手機 fallback 的佔位 `<div>` **必須用同一個數字**，否則 iframe 決定載入的瞬間會有高度跳動（CLS）。
- **demo 內的「探索進度」步驟列位於 `topbar` 與 `stage` 之間，是文件流的一部分**（2026-09-05 自左下角浮層移入）。原本 `position: fixed` 的版本在 720px 高的 iframe 裡會整個蓋住第 3 張卡片，並壓過 App 視窗的圓角邊界。**不要改回 fixed。**
- **舞台刻意不吃全站的 `xl:px-24 2xl:px-60`**：demo 是兩欄並排的桌面 App 畫面，套上全站留白在 2xl 螢幕只剩約 1120px，兩側都被擠到換行。聲明與 CTA 是純文字，維持全站閱讀寬度。
- 主題同步走**同源 iframe 才做得到的路徑**：父頁以 `MutationObserver` 盯 `documentElement` 的 class，直接改 iframe 內文件的 class。**`demo-app/index.html` 因此一行都不用改**。⚠️ 不能改用 `useTheme()` 的 `isDark` 來 watch —— 那支 composable 每次呼叫回一個獨立的 ref，AppHeader 切換時本頁的 ref 不會動。
- **主導覽只對 `zh-TW` 露出**（`AppHeader.vue` 的 `NAV` 為 locale 條件式 computed）。`/en/demo` 路由仍然存在，入口只有 `/en` 首頁那一段的 CTA。
- 🔴 **因此 `/en/demo` 的入站連結只有一條。** `nuxt.config.ts` 的 `nitro.prerender.routes` 已明列它 —— 首頁那段哪天被改掉或藏起來，沒有這一行就會無聲變成 404（同 `/enterprise` 的坑，見 [08](08_enterprise.md) §1）。

### 【推論分類】

**產品體驗頁（Product Experience），形式為受控的功能模擬。**

判定依據：本頁不傳遞新的事實，也不承載交易路徑 —— 它把 [01](01_index.md) §2 已經用靜態圖講過的「本機 →〔需授權〕→ AI」流程，改成一個可以親手操作的狀態機。它服務的是**安裝前的最後一段疑慮**：要不要把一個 Electron App 裝進自己的電腦。

因此它在漏斗上的位置是 **`/`（入口）→ `/demo` → `/download`**，與 [02_download.md](02_download.md) 直接相接。

## 4. 問題解決與意圖解析 (Problem Resolution & Intent)

### 【事實】

本頁不提供任何可下載或可購買的東西。唯一的產出是「訪客親手操作過一次授權流程」這個經驗。

### 【推論】

從**外連 CodePen 被否決**這件事，可以反推本頁的約束條件。當初的候選是把 demo 掛到 CodePen 換取開發者社群的散布力，被否決的四個理由裡有兩個是本頁的形態決定因素：其一，剪貼簿 API 在跨網域 sandbox iframe 很可能失效，而第一步就是複製；其二，**產品主張「本地端、資料不外流」，卻把示範託管在第三方 SaaS 並請人在裡面輸入密碼欄位**，那是自相矛盾的氣味。

從**首頁只放截圖不 inline demo** 這件事，可以反推另一組約束：首頁是全站 LCP 最敏感的一頁，而 [效能待改清單](../../webplan/效能待改清單.md) 的 E1–E7 尚未動工。在那之前往首頁加 80K 的死重，順序是反的。

### 【價值判斷】

本頁解決的是**「安裝一個會保管你密鑰的桌面程式」這件事的信任落差**。

這類產品的說明頁通常有三種做法：錄一段剪過的影片、放一組靜態截圖、或讓人真的動手。前兩種的共同問題是**訪客無法區分「產品真的這樣運作」與「示範被剪成這樣」** —— 而那恰好是安裝一個保管密鑰的工具時最該問的問題。第三種的代價是必須把真實行為搬進瀏覽器，而搬運過程一定會失真。

本頁選第三種，並且**把失真本身寫在頁面上**（示意聲明），而不是希望沒人注意到。這與 [08](08_enterprise.md) 選擇如實呈現空名單、[07](07_what-we-dont-do.md) 以否定式構成主要內容，是同一種取捨。

⚠️ **本頁最容易被侵蝕的地方**：示意聲明是 demo 內容凍結的交換條件，而它讀起來像一句可有可無的免責聲明。哪天有人為了版面清爽把它拿掉，**demo 裡那三處與 App 不符的細節就變成沒有依據的對外主張**，而沒有任何一支護欄會報錯。它的守衛只有 `demo.vue` 的檔頭註解、本文件，以及 [主張與依據 §二之四](../主張與依據.md) 第一列。

### 🔴 兩件已知、且刻意沒有解決的事

1. **demo 本體與 App 有三處不符**（工具名、port、`variables:` 那一行），創辦人 2026-09-05 決定不修，改以聲明處理。要修的正確順序是先改 `demo-app/index.html`、再回頭刪聲明 —— **反過來做會有一段時間是裸奔的**。
2. **demo 內文沒有 i18n**，因此英文使用者拿到的是英文外殼包中文內容。要對 `en` 開放主導覽，前置條件是把 demo 文案抽出來翻譯（那份檔案有自己的 DOM 操作，不是換幾個字串就好），然後刪掉 `AppHeader.vue` 裡的 locale filter。
