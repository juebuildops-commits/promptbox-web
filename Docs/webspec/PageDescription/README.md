# 頁面分析索引（PageDescription）

本目錄收錄 `Src/` 網站專案的**資訊架構與意圖分析**。每個路由對應一份文件，各文件皆依同一四模組框架撰寫：頁面類型定義、核心內容映射、連結拓樸分析、問題解決與意圖解析。

分析對象限於結構、語意與意圖，不涉及視覺設計、版面配置與前端實作。

## 三、站台層級的連結拓樸

### 資訊流動的主幹

```
                      ┌─────────────┐
                      │  首頁（Hub） │
                      └──────┬──────┘
                 分流 ┌──────┴──────┐ 分流
                      ▼             ▼
              ┌──────────────┐  ┌──────────────┐
              │ 下載（交付）  │  │ 定價（意向）  │
              └──────┬───────┘  └──────┬───────┘
                     │                 │
        風險揭露 ────┼──────┐          │ 三個購買行動點
                     │      ▼          │ 全部落在頁內表單
                     │  /docs#install-safety
                     │      │
                     ▼      ▼          ▼
              ┌────────────────────────────────┐
              │  /api/subscribe（唯一伺服端點） │
              └────────────────┬───────────────┘
                               ▼
                      Buttondown 名單服務（外部）
```

### 三個結構性事實

1. **email 收集是全站唯一的轉換終點。** 首頁（新版通知）、下載頁（新版通知）、定價頁（早鳥登記＋商業諮詢）、更新日誌（新版通知）、隱私權頁（聯絡管道）、支持組織頁（商業諮詢）**六個頁面共嵌入七處**（隱私頁與支持組織頁那兩處是條件式的：設定了 `NUXT_PUBLIC_CONTACT_EMAIL` 時改為 `mailto:`）。全站不存在交易節點、帳號註冊或登入。
2. **對外出站連結極少且集中。** 使用者可直接觸發的站外導航僅四處：下載頁的兩個安裝檔位址（物件儲存）、手冊第 8 章的程式碼代管平台、手冊第 9 章的第三方檔案掃描服務。其餘所有第三方（金流平台、名單服務、託管商、分析服務）皆僅以文字指名，不提供路徑。
3. **跨頁深層錨定僅有一組。** 下載頁 -> `/docs#install-safety`，反向則有手冊第 1、9 章 -> `/download`。此為全站唯一的雙向主題耦合，其主題是安裝安全性。

### 已辨識的拓樸缺口

- **首頁四個主要下載行動點指向不存在的片段識別**（`#download-win`、`#download-mac`），位置分別在頁面最上方與最下方的轉換入口。詳見 [01_index.md](01_index.md) §3。
- **隱私權頁的第三方處理者矩陣未連往各服務的政策**，使資料流向的查核鏈在指名後中斷。詳見 [06_privacy.md](06_privacy.md) §3。

## 四、站台層級的意圖結構

全站八個頁面在業務流程中的職能可歸納為三層：

| 層 | 頁面 | 職能 |
| --- | --- | --- |
| **說服層** | 首頁、定價、**支持組織**（2026-08-31 增） | 建立產品範疇認知與價值判斷；將不可觀察的隱私屬性轉為可查核的機制陳述；界定交易條件與長期風險。支持組織頁是其中唯一**面向組織採購**的一頁，且它說服的方式是把空名單如實攤開 |
| **交付層** | 下載、手冊 | 完成物件交付與完整性驗證；降低非直觀概念的認知門檻；承接安裝中斷點的信任修復 |
| **佐證層** | 更新日誌、隱私權、**我們不做什麼**（2026-08-30 增） | 以可稽核的紀錄佐證維護活躍度；以可行使的控制項佐證隱私主張；以自我約束的公開清單降低推薦者的背書成本；處理「不連網的產品其官網卻有分析」這一結構性矛盾 |

全站共同解決的核心資訊落差是：**本地優先、加密、不連網等屬性在購買決策點上不可觀察**。六個頁面以不同形式回應同一問題——首頁以機制指名、下載頁以校驗碼、手冊以概念形式化與第三方查證途徑、更新日誌以時間軸紀錄、隱私權頁以可執行的退出開關。其共同策略是**將需要被相信的主張，轉換為可被查證的形式**。
