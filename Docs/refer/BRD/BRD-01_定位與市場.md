## 1. 市場定義

> **PromptBox 競爭的市場是：非技術 AI 重度使用者的本機機密 context 保險庫。**

壟斷程度取決於市場切得多細。同一個 PromptBox 在三種市場定義下勝算天差地別：

| 市場定義 | 主要對手 | 勝算 | 判斷 |
|---|---|---|---|
| 筆記／知識管理工具 | Notion、Obsidian、Apple Notes | 極低 | ❌ 太寬，沒有立足點 |
| Prompt 管理工具 | PromptHub、SpacePrompts、Keep My Prompts、PromptLayer | 低 | ❌ 紅海且多為工程／團隊向 |
| **非技術 AI 重度使用者的本機機密 context 保險庫** | 幾乎無明確佔位者 | 高 | ✅ **採用** |

三個限定詞各排除一批競爭者：

| 限定詞 | 排除了誰 |
|---|---|
| **非技術** | PromptHub、PromptLayer、Langfuse 等工程／LLMOps 向工具 |
| **本機** | 幾乎所有 SaaS prompt 管理器（其價值主張建立在雲端同步與協作上） |
| **機密／密鑰** | Notion 與記事本（不敢放密鑰），以及純 prompt 工具（沒有密碼鎖與釋放稽核） |

1Password／Bitwarden 佔的是「**密碼**」保險庫，不是「**context**」保險庫——「消費級、AI-native 的 context 保險庫」目前確實是空的。

## 2. 定位語句（對外統一口徑）

**主打（安全帳戶錨定）**

> **「AI 時代的密碼管理器——但存的是你的 prompt、設定與密鑰。」**

**副標（中立錨定）**

> **「你的 context，存在你自己的電腦；任何 AI 都能用，任何廠商都拿不走。」**

**為什麼是這兩句**：主打句直接把使用者的參考價格從「記事本＝免費」搬到「密碼管理器＝$20–48/年」——這是 $39 定價成立的心理基礎（見 [BRD-02 §3](BRD-02_商業模式與定價.md)）。副標句守住中立這條最難被大廠複製的護城河（§5）。

**備用（痛點錨定，用於廣告與社群貼文開頭）**

> 「把 API key 貼在記事本裡，然後整包丟給 AI？換一個作法。」

## 3. STP：三圈客群

**只在第一圈做行銷，第二三圈只做「不擋路」。**

| 圈層 | 誰 | 為什麼是他 | 現階段動作 |
|---|---|---|---|
| **第一圈｜灘頭堡** | SEO 寫手、AI 影像／文案創作者 | 高頻使用 prompt，會存 API key，但不會自架工具 | **全部行銷資源投這裡** |
| **第二圈｜擴散器** | n8n／自動化玩家、獨立開發者 | 人數比第一圈少，但**傳播力遠高**，且是 MCP 的天然使用者 | 做好文件與模板，讓他們替你寫教學 |
| **第三圈｜未來營收** | 2–5 人小型代理商／工作室 | 有共用密鑰的真實痛點，願付單價高 | 只留一個「商業授權」按鈕，不做銷售 |

第二圈不是主要付費來源，是**行銷通路**。n8n 玩家會寫教學、錄影片、發模板，一個人可以帶來幾百個第一圈用戶。

### ⚠️ H1：第一圈受眾是**未驗證假設**，不是數據

> **這是本冊最重要的一條標記。**

ADR-003 原文把受眾寫成「真實受眾與競品（**來自實際使用者數據**）：SEO 寫手、AI 影像創作者」，`_archive/Business Decisions.md` §2.2 據此稱他們「已是實際使用者（**有真實數據**）」。

**但 PromptBox 尚未發布、沒有任何使用者**（2026-07-31 創辦人確認）。所以這**不是數據，是假設**。

| 項目 | 內容 |
|---|---|
| **假設編號** | H1 |
| **假設內容** | 首發後的主要使用者是 SEO 寫手與 AI 影像／文案創作者，其比較對象是 Notion / NotebookLM / 記事本 |
| **依賴它的決定** | 整個 §3 STP、§4 價值曲線的取捨、[BRD-03](BRD-03_授權與Free-Pro邊界.md) 的付費牆位置、[BRD-05](BRD-05_行銷與獲客.md) 的通路優先序 |
| **若被推翻的後果** | 若實際來的是**開發者** → 強型別完全隱藏（BRD-03 B7）是錯的；若實際來的是 **n8n 玩家** → 主鉤子該是 MCP 而非機密卡片 |
| **驗證時機** | **首發後第一件要用數據確認或推翻的事** |
| **驗證方式** | 首發 90 天內的使用者來源（referrer）、下載頁問卷、社群互動來源分布 |

**紀律**：下游文件引用受眾時，**必須連 H1 標記一起引用**。不得讓一個猜測以「真實數據」的身分傳到 PRD。

## 4. 價值曲線：主動放棄什麼

重點不是「加什麼」，而是「敢減什麼」。

**大幅拉高（差異化來源）**

- 安全可驗證性（開源核心、靜態加密、釋放稽核）
- 認知負荷低到極致（比 Notion 更簡單，這是刻意的定位選擇）
- 中立性（不綁任何 AI 廠商 / IDE）

**維持及格**

- MCP 相容性、多語系、跨平台

**主動放棄（公開明講「我們不做」）**

| ❌ 不做 | 為什麼 |
|---|---|
| 團隊協作與權限管理 | 與 local-first 隱私定位對撞，且要你營運後端 |
| 雲端同步當賣點／主要營收 | 與隱私定位正面衝突，會拖進 SaaS 成本結構 |
| Prompt 版本控制、A/B 評測、成效追蹤 | 工程師向功能，堆到非技術用戶學不會 |
| Prompt 市集／社群瀏覽 | 與中立定位無關的營運負擔，且抽成模式已排除 |
| 廣告、資料變現、市集抽成 | 直接摧毀信任定位 |
| 硬 DRM / 密碼狗 | 為防賊犧牲體驗，護城河不是 DRM |

> **放棄清單本身就是行銷素材。** 工程向工具堆功能堆到非技術用戶學不會——**你的「少」在第一圈客群眼中是優點而非缺點**。這份清單要做成一頁公開的「我們不做什麼」，首發即上（見 [BRD-05](BRD-05_行銷與獲客.md)）。
>
> ⏸️ **2026-09-03 更新：那一頁暫時不上**（創辦人：語氣過死）。頁面做好了、也還在 `/what-we-dont-do`，但已撤出官網頁尾導覽、站內無入口。
> **上表六條放棄本身完全不受影響** —— 它們仍是定位的一部分，仍拘束產品與文案（[BRD-03 §6](BRD-03_授權與Free-Pro邊界.md) 的不做硬 DRM 就依賴這張表）。
> 暫緩的只有「把它做成一頁公開頁對外講」這個行銷動作。

## 5. 競品對標

**主對標（使用者腦中真正的對手）**：Notion / NotebookLM / 記事本

**次要參照（同業，但不是使用者的比較對象）**：PromptHub / SpacePrompts / Keep My Prompts / PromptLayer

> **這是一次刻意的修正。** 舊的競品分析以 PromptHub 為主要對手——但（依 H1 的假設）使用者腦中根本沒有 PromptHub。**瞄錯了靶。**
> 真正的賽道不是「工程師的 Prompt/Skill 工作台」，而是「非技術大眾的、簡單的、AI 可取用的個人機密 context 儲存」。
> 比較頁的寫法：誠實列出對手的優點（這反而增加可信度），再點出三個限定詞。**不誠實的比較頁在這個客群裡會被立刻識破，而且會傷害信任定位。**

## 6. 護城河與必須接受的張力

### 6.1 三層疊加的護城河

| 層 | 內容 | 可複製性 |
|---|---|---|
| **中立的跨平台 context 互通層** | 大廠只會做**綁自己 IDE** 的基建，**結構上不會做**「大家都能一起用」的中立基建，因為那違背其鎖定利益 | **平台結構上做不到**——最強的一層 |
| **簡單（認知負荷最低）** | Notion 已經這麼簡單仍一堆人學不會 → 不該高估使用者學習力 | 易被複製，須與中立 + 安全綁定才立得住 |
| **安全（機密鎖好不外洩）** | 見 [ADR-003](../ADR/ADR-003-soul.md)：安全是產品本體，不是 infra 衛生 | 需持續投資，且是責任而非只是賣點 |

### 6.2 必須接受的張力

| 張力 | 說明 | 處理 |
|---|---|---|
| **中立 = 無鎖定 = 無定價權** | 讓你可辯護的東西，同時讓你難收費 | **接受它。** 定價權不來自鎖定，來自**信任**與**轉換成本**（卡片庫越大越難搬）。這也是把價格訂在同業最低的理由——**你在打價值戰，不是定價權戰** |
| **大眾 vs MCP 設定門檻** | 最容易的使用者最不可能自己設定 MCP | 已決議：**做 MCP 一鍵接入**（匯出 Claude Desktop / Cursor 設定檔），且付費牆刻意設計成四個觸發點、其中兩個不依賴 MCP（見 [BRD-03 §4](BRD-03_授權與Free-Pro邊界.md)） |
| **安全即賣點 = 安全即責任** | 一旦主打機密，任何外洩事件對品牌是致命的 | 這是選擇這條賽道的固定成本。對應動作見 [BRD-05](BRD-05_行銷與獲客.md) 的第三方稽核與公開威脅模型 |

## 7. 目標與歸宿

> **現金流優先。「拚規模、被收購」是長期選項，不是當期目標。**

| 項目 | 定案 |
|---|---|
| **北極星** | **12 個月內驗證出可重複的付費轉換** |
| **輸入指標** | 裝機量（不是北極星） |
| **輸出指標** | **付費留存** |
| 長期選項 | 被收購仍是合理歸宿（本質是基礎建設，不會是獨角獸），但**不是現在要優化的目標** |

**為什麼順序是現金流在前**：

- **對收購方而言，有付費留存數據的產品估值邏輯更硬。** 「10 萬裝機、零營收」只能用 acqui-hire 或 traffic 邏輯估值；「3 萬裝機、5% 付費、高續訂」可以算出 CLV 並用倍數估值。**付費數據不是融資的替代品，是融資的彈藥。**
- **訂閱經濟有「死亡低谷」**：獲客成本一次性前置、收入分期進帳，越衝規模短期現金流越差。沒有外部資金時先拚規模，是最容易死的走法。
- **企業經營的重點不是成長，而是要賺錢。**

具體的營收里程碑見 [BRD-02 §5](BRD-02_商業模式與定價.md)。
