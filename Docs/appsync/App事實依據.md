## 二、🔴 誠實紅線：管的是官網「可以寫什麼」

這兩條與上面六條性質不同——**上面六條是「App 做了什麼」，這兩條是「官網被允許怎麼說」**。
它們是 [主張與依據](../webspec/主張與依據.md) 這份文件存在的上位原因。

### C1　不得在任何介面或文案暗示超出實際的保護

例：不得暗示機密卡片「解鎖後所有欄位皆受保護」、不得說「Pro 讓你的資料受加密保護」（加密在 Free 就是完整的，說成 Pro 特性等於兩頭都不誠實）。

### C2　已知邊界必須明列，不得模糊

**目前四條**（2026-08-23 起，由五條回到四條）：

1. 機密卡片的**變數預設值是明文**
2. `safeStorage` 不可用時**退回明文開庫**
3. **離線 ⊥ 防破解**（見 B6）
4. **main 無法保證 renderer 的明文被抹掉** —— 人類側解鎖的明文活在 renderer，main 只能「請求」它清理；對照 AI 側授權窗完全由 main 持有、wipe 是確定的。**兩側保證強度不同，文案不得混為一談**

> **為什麼誠實是紅線而不是美德**（App repo ADR-000 §3.3 原文的理由）：
> 產品的獲客放棄了利益誘因型裂變，改押在「**可驗證性**」上降低推薦者的背書成本。
> **在文案上說謊會直接砸掉這個機制**，而它是這個產品唯一的推薦背書路徑。
>
> 官網這一端的具體後果：下載頁 `notes.n4` 主動承認「Windows 會顯示無法辨識的應用程式」、
> mac 卡片顯示「即將推出」而不給假的下載鈕、GA4 未設定時隱私頁誠實說「本站目前未設定任何分析工具」
> —— 這些都不是文案風格選擇，是 C2 的執行。

## 三、B5 護欄測試：2026-08-29 實測結果

> ⏳ **這一節會在 App v3.7.2 出貨後過期（W5），但現在不要改。**
> 出貨後護欄會涵蓋 12 條以上，下面「只釘住兩個」的結論就不再成立。
> **在那之前它是準確的** —— 提早改等於提前說謊（誠實紅線 C2）。出貨日見 [SYNC-000 §五 Q2](SYNC-000_索引與雙方進度.md)。

[主張與依據](../webspec/主張與依據.md) 原本掛著一條「B5 護欄測試的斷言是否已更新**未確認**」。已查核，結論如下。

`electron/__tests__/data-continuity.test.js`（89 行）目前斷言：

| 斷言 | 值 |
| --- | --- |
| `build.appId` | `com.promptbox.app` |
| `build.productName` | `PromptBox` |
| `pkg.main` | `electron/main.cjs` |
| `electron/` 原樣進 asar | ✅ |
| `electron/__tests__/` 排除在打包外 | ✅ |

🔴 **它只釘住 `appId` 與 `productName` 兩個身分字串。**
[身分字串凍結清單](./身分字串凍結清單.md)「護欄」一節要求擴充的另外四項——
**userData 路徑、金鑰庫識別字串、DB 檔名 ×2、MCP server 識別**——**目前都還沒有斷言**。

對官網的意義：下載頁「升級覆蓋安裝、資料原地保留」這句話，**目前只有一半有護欄保護**。
`appId` 不會被改壞（有測試），但 userData 路徑與金鑰庫識別**改了不會有任何東西擋**。
這條在改名執行前必須補上，否則那句文案的依據強度低於它讀起來的樣子。
