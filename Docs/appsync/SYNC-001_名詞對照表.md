> **這份文件解決的問題**：同一個詞在兩個 repo 指不同東西，或同一件事有七個叫法。
> 這不是預防性的整理 —— **已經踩到過兩次**：官網文件寫 `mcpServers.promptbox`（小寫）對不上
> App 的 `PromptBox`；[ADR-008 §七](ADR-008_授權憑證格式與離線驗證契約.md) 寫的

>
> 🔴 **本表只放「一句話 + 正本連結」，不放定義的完整內容，一個數字都不寫**
> （數字一律引用 BRD，App repo `ADR-000 D1`）。**表本身永遠不是最終答案**，每一列都指得出正本。

## 〇、怎麼看、怎麼填

### 符號

| 符號 | 意思 |
| :-: | --- |
| ✅ | **我這一側查過，就是這樣** |
| ⚠️ | **有疑慮** —— 我這側和表上寫的不一致，或我認為該改 |
| ❓ | **不知道** —— 沒查過 / 查不到 |
| ➖ | **不適用** —— 這個詞在我這一側不存在 |

**兩邊都 ✅ ＝ 對齊。**

### 🔴 兩條規則

**① App 端那一欄，官網一格都不填。**
一個「兩邊都勾才算對」的機制，如果一邊是另一邊代填的，**整個機制就失效了** ——
它會退化成官網自己跟自己確認。所以初版整欄是 ❓，那不是偷懶，那是誠實的起始狀態：
**它顯示的正是「還沒有人跨 repo 對過」**。

官網認為某個詞不屬於 App 的，在「是什麼」欄標 `🌐 官網側概念`，
**但那一格的勾仍然留給 App 自己打**（該打 ➖ 還是 ❓，由 App 決定）。反向同理（`📱 App 側概念`）。

**② 任何一格是 ⚠️ 或 ❓ ⇒ 那一列自動是待確認項。**
匯總到 [SYNC-000 §五](SYNC-000_索引與雙方進度.md)，兩份文件不要各走各的。

### 勾選要不要寫日期

**預設不寫**，日期看上面的「最後對齊日」。
**只有個別列在對齊日之後才有異動**時，在該格寫上日期（例：`✅ 09-15`），
免得整欄看起來都是最新的。

## 五、維護

| 觸發 | 動作 |
| --- | --- |
| 對面回填了勾選 | 更新檔頭「最後對齊日」；出現 ⚠️／❓ 的列 → 同步到 [SYNC-000 §五](SYNC-000_索引與雙方進度.md) |
| 某個詞的正本改了定義 | 改「是什麼」那一句 **＋ 把兩側的勾降回 ❓** —— 定義變了，先前的確認就失效了 |
| 又踩到一次名詞誤解 | 新增一列，並註明是哪一次踩到的（本表現有兩列就是這樣來的） |
| 某個詞不再有誤解風險 | **不要刪**，標記即可。刪掉之後，下一個人會重新踩一次 |

> **這份表的失敗模式是「開了、填滿、然後沒人更新」**，半年後它會比沒有更糟，因為它看起來很權威。
> 唯一的緩解是每一列都指得出正本：**即使某列過期，讀者也會被導到正本**。
> 所以「正本」那一欄是本表最重要的一欄 —— **比定義還重要**。
