# SYNC-000｜索引與雙方進度（Cross-Repo Sync Index）

> **這份文件解決的問題**：`Docs/appsync/` 底下五份文件各自回答一個題目，但**沒有一份說「現在跑到哪」**。
> App 端讀完全部五份，不會知道官網階段五六是刻意暫緩的、更不會知道在等什麼；
> 官網這一端也是查了才知道 v3.7.2 已經立案。**兩邊各自都有進度，只是對方看不到。**
>
> 🔴 **這份只放「狀態」與「指路」，一個規格、一個數字、一條決策理由都不放。**
> 需要內容一律點過去 —— 正本永遠不要有兩份（[文件規則 §6](../文件規則.md)）。
>
> **正本**：本檔在官網 repo `Docs/appsync/`。App repo 若要引用，放**指路存根**，不要複製一份。
> 📌 **維護規則：每一側只改自己那一欄。** §二 的「官網」欄由官網 repo 維護、「App」欄由 App repo 維護。
> 改對方那一欄之前先確認，否則這份會變成第六份沒人信的文件。
>
> 📌 **App 程式碼與文件路徑一律寫成純文字不做連結**（在官網 repo 點不開）。起點是 App repo 子專案目錄 `PromptBox/`。
>
> **最後同步日**：2026-09-14

### 3.3 接起來之後浮出的兩件事

**① 四條線的根是同一個沒人在推的決定。**
階段六、P6、P7、以及官網全站的 A 類品牌字串替換，**全部掛在「產品名拍板」下面**。
公司身分已於 2026-08-28 拍板（覺構 / JueBuild，見 待討論問題 §八 D31），
**但產品名沒有** —— 而 `productName` 依 [App 側回覆](App側回覆.md) §1.2 是「不凍結、隨品牌走」，
所以 8/31 的身分字串拍板**沒有連帶解決它**。

**② 官網與 App 在互等（已由 2026-09-14 拆分階段五六打破死鎖）。**
原先官網階段五六等 App 雙 build；而 Build B 的定義就含 Ed25519 驗章（BRD-00 §3.2.1），
App 側把它排在「官網會員區做完」之後（[App 側回覆](App側回覆.md) §四）。兩邊都在等對方。

> 💡 **2026-09-14 已拍板解法**：正式將原 PRD 拆分為獨立的 [PRD_階段五_會員與帳號中心](../webplan/PRD_階段五_會員與帳號中心.md) 與 [PRD_階段六_金流與授權發放](../webplan/PRD_階段六_金流與授權發放.md)。
> 官網率先啟動 **5a+**（Supabase Auth + 帳號頁 + 早鳥資格綁定 + Ed25519 測試向量），不碰錢、不依賴 App 產物，為 App 端提供設定頁 UI 參考與測試向量，**正式打破雙邊互等死鎖**。
