# 身分字串凍結清單（Identity Freeze Checklist）

> **用途**：在**發出任何安裝檔之前**，把一批「使用者看不到、但決定他們的資料還在不在」的字串一次定死。
> **觸發原因**：產品即將因商標問題改名，同時要在比賽釋出 Free 版。
> **建立**：2026-08-27　**狀態**：⏳ 待執行，**且必須在發 binary 之前**
> **2026-08-30 更新**：步驟 0 已答 —— **沒有既有使用者 ⇒ 走 §B 重選分支**。
> **2026-08-31 更新**：字串已由創辦人選定，見 **§B**。實作在 App repo（v3.7.2），**尚未出貨**。
> **範圍**：主要在 App repo（`PromptBox`）。官網只受 A 類影響。

---

## 為什麼有這份清單

改名影響的東西分成兩類，而它們的風險差了好幾個數量級：

| | A 類：品牌字串 | B 類：身分字串 |
| --- | --- | --- |
| 例 | 官網文案、視窗標題、關於視窗 | `appId`、Keychain service 名稱、DB 檔名 |
| 使用者看得到嗎 | 看得到 | **看不到** |
| 改了會怎樣 | 沒事 | **既有使用者的資料變孤兒，或永久解不開** |
| 怎麼改 | `sed 's/PromptBox/新名字/g'`，一行 | **不改。永遠不改** |

A 類**不需要任何預留設計**。`PromptBox` 是個獨特的專有名詞，全域取代不會誤傷；為它做參數化只會讓語系檔變難讀。

B 類是這份清單的全部內容。

> **一句話**：品牌名字可以換，身分字串不能。
> Firefox 的設定檔路徑到今天還寫著 `Mozilla` —— 那不是遺留問題，那是正確做法。

## §B 重選分支：完全沒有既有安裝時

這是最後一次自由選擇的機會，選了就變成 §A。

建議原則：

1. **身分字串用一個中性、不會再改的識別**，不要用品牌名。
   例如 `com.<你的網域>.app` 這種形式 —— 但網域也可能改，所以更保險的是一個**你確定永遠屬於你**的字串。
2. **一次選好，同一天寫進護欄測試**，不要留到「之後再說」。
3. A-4 的檔名可以順勢改成中性名（例如 `vault.db`），這樣未來任何改名都不會碰到它。

#### 🔴 為什麼是 `eychen` 而不是 `juebuild`／`vault`

| 候選 | 為什麼沒選 |
| --- | --- |
| `juebuild`（公司） | 公司身分雖已於 2026-08-28 拍板（覺構 / JueBuild，見 [待討論問題 §八 D31](../webplan/待討論問題.md)），但**公司會改名、會解散、會被併購**。它不滿足建議 1 的「你確定永遠屬於你」 |

**這正是建議 1 的兌現**：「更保險的是一個**你確定永遠屬於你**的字串」——

>

> **改名讓資料變孤兒是災難**。用一個永遠不會過期的識別換掉一個永遠不會發生的災難，划算。

> **那一個是會出現在使用者眼前的**（macOS 鑰匙圈對話框），和這裡的路徑不同，
> 觀感在那裡就不是可以隨手接受的東西了。

## 🔴 驗收：唯一能證明沒弄壞的方法

程式碼審查證明不了這件事。**必須實機跑一次**：

1. 用**改名前**的建置安裝
2. 建立一些資料：普通卡片、**一張有密碼的機密卡**、一個 MCP Token
3. 完全關閉
4. 用**改名後**的建置**覆蓋安裝**（不是先解除安裝）
5. 開啟，確認：
   - [ ] 卡片全在，數量一致
   - [ ] 🔴 **機密卡能用原密碼解開**（這一步證明 A-3 沒破）
   - [ ] MCP Token 還在，IDE 連得上
   - [ ] 設定（主題、變數替換開關）保留
   - [ ] 「程式集 / 應用程式」裡**只有一個**，不是兩個（這一步證明 A-1 沒破）

Windows 與 macOS **各跑一次**。兩邊的失敗模式不同，過了一邊不代表另一邊沒事。

> 🔴 **2026-08-30 補記：這一節的前提在 §B 分支下不成立。**
>
> 上面整套驗收要證明的是「**既有資料**在改名後還在」。走 §B 代表沒有既有資料，
> 因此步驟 1「用改名前的建置安裝」→ 4「覆蓋安裝」這條路徑**沒有東西可以驗**。
>
> 而且 **macOS build 根本不存在**（[前置鏈 P3/P4](../webplan/上線前置鏈.md) 未啟動，
> 首頁 CTA 已於 2026-08-30 改為「macOS 版即將推出」），那一次驗收**跑不了**。
>
> **§B 分支下要驗的是另一件事**：新字串**確實被寫死了**，而不是又被推導出來。
> 做法是拿新建置安裝 → 建資料 → **改一次 `productName`** → 覆蓋安裝 →
> 確認資料還在。也就是把「改名」當成測試手段，而不是等真的改名時才知道。
> 這一次 Windows 跑就夠了；macOS 等 P4 有 build 之後補跑，
> **在那之前不要宣稱 macOS 這條已經驗過**。
