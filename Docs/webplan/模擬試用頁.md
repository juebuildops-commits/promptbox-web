## 1. 這件事在解什麼

`Docs/APPsim/APPsim.html` 是一份 1857 行、零外部依賴的互動示範：左邊是 PromptBox 卡片盒，
右邊是模擬的 IDE，四步引導走完「複製 → 啟動 MCP → 對 AI 隱藏 → 機密釋放授權」。

**它要解的疑慮是「我得先裝一個 Electron App 到自己電腦上」。** 所以它的位置不是首頁主秀，
是漏斗中段：**首頁（入口） → `/demo` → `/download`**。

### D10：為什麼 `en` 不能比照 `ja` 留空

`check-i18n.mjs` 只把 **`ja`** 放進 `SKELETON`，其餘語系走這一條：

```js
if (value === '') {
  if (!isSkeleton) errors.push(`… \`${key}\` 是空字串（出貨語系不得留空）`)
}
```

`en` 是**出貨語系**，留空 ⇒ `npm run build` 直接紅。

**不要為此把 `en` 加進 `SKELETON`**——那會讓全站的英文都可以留空，等於為了一個頁面拆掉整支護欄。

**做法**：`en` 照常填英文。範圍其實很小——只有外殼那層（頁標、一段說明、示意聲明、手機提示、兩顆 CTA、nav 一個字），
**大約 8 條 key**，demo 內文（iframe 裡那 1857 行）完全不用翻。
「接縫」還是做好了：key 結構在、`nuxt.config.ts` 註冊在，只是值是真英文而不是空字串。

`ja` 維持骨架（空字串），照 D-16 不變。

## 5.6 步驟列改版（2026-09-05 第二輪）

**問題**：「探索進度」原本是 `position: fixed; left:20px; bottom:20px` 的浮層。在 720px 高的 iframe 裡
量到**與第 3 張卡片重疊約 53px**（卡片列到 y≈528，面板頂在 720−20−225＝y≈475），
整張「內部 API 命名規範」的下半截與複製鍵被蓋住；而且因為是相對 iframe viewport 定位，
它還**壓過 App 視窗的圓角邊界**。

**做了什麼**：

| # | 改動 | 檔案 |
| --- | --- | --- |
| 1 | `.guide` 移進 `.page` 的文件流，位於 `topbar` 與 `stage` 之間；視覺語彙對齊 `.mcp-bar` | `demo-app/index.html` |
| 2 | `.guide-body` 由直排改 `grid-template-columns: repeat(4, 1fr)` 橫向單列；`.guide-done` 加 `grid-column: 1 / -1` | 同上 |
| 3 | 🔴 **對比反轉**：未完成 `--text-main`（原 secondary）、已完成 `--text-secondary`（原 main） | 同上 |
| 4 | 空心圓改**編號徽章**，以 `counter-reset`／`counter-increment`／`.mark::before` 純 CSS 實作 | 同上 |
| 5 | **「下一步」單條高亮**，以 `.step[data-done="false"] ~ .step[data-done="false"]` 反選其餘 | 同上 |
| 6 | iframe 與手機佔位高度 720 → **780**（兩處必須同步，否則 CLS） | `demo.vue` |
| 7 | 🔴 **步驟本文字級 12 → 16px**，行高 1.4 → 1.5，徽章 18 → 22px，標頭 12/11 → 14/13px | `demo-app/index.html` |
| 8 | 🔴 **整條改用 `.mcp-bar` 的中性↔`--success` 狀態語彙，移除所有 `--primary`** | 同上 |

🔴 **3–5 全部是純 CSS，`<script>` 一行都沒動。** 選這條路是為了讓行為零風險 ——
`renderGuide()` 產出的 DOM（`.step[data-done]` + `.mark` + `.txt`）本來就夠用。

**為什麼是 16px（創辦人 2026-09-05 決定）**：**寧可換行也不要看不清楚。**
這是一份要照著做的操作清單，不是註腳；為了省高度把字改小，等於讓它回到沒人讀的狀態 ——
而那正是它原本擺在左下角浮層時的問題。理由已寫進 `index.html` 的 CSS 註解，
免得日後有人為了擠空間又改回去。

⚠️ **代價（已知、接受）**：每格從約兩行變兩到三行，步驟列高度由約 64px 長到約 90px。
`.guide` 在文件流裡 ⇒ **不會再壓到卡片**，長高只會讓兩個視窗變矮。
若要把視窗高度補回改版前的水準，把 `demo.vue` 的兩處 `min-height` 由 780 再調到 820 即可
（**兩處必須同號**）。目前刻意先不調，等實際看過畫面再決定。

**配色（創辦人 2026-09-05 決定）：整條任務列改用 `.mcp-bar` 的狀態語彙，不用品牌青藍 `--primary`。**

> 🔴 **真實 App 裡沒有這條任務列** —— 它是示範用的鷹架，不是產品的一部分。
> 套上品牌色會讓它讀起來像個功能；它該表達的是**臨時狀態**，所以借用同一頁上方
> `.mcp-bar` 已經在用的那套：**中性灰（尚未）↔ `--success` 綠（已完成）**，
> 連 `.led.on` 那圈 `0 0 0 3px` 光暈都照抄。

| 狀態 | 取自 | 值 |
| --- | --- | --- |
| 尚未輪到 | `.mcp-bar`（未啟動） | 透明邊、無底色、`--border-light` 徽章、`--text-secondary` 編號 |
| **下一步** | 無對應 —— 靠**重量**而非色相 | `--text-main / .22` 邊、`/.04` 底、`/.55` 徽章 + `/.06` 光暈、深色編號 |
| 已完成 | `.mcp-bar.on` 逐值照抄 | `--success / .45` 邊、`/.06` 底、實心綠徽章 + `/.2` 光暈 |

狀態只有兩色可用而步驟有三種狀態，所以「下一步」用重量區分。已完成的綠底維持 `.06` 這種極淡的量，
加上內文本來就是 secondary + 刪除線 ⇒ **「未完成比已完成顯眼」那條原則不會因為多一層綠底而翻掉**。

標頭的計數（原 `--primary`）改 `--text-main`（那是數據不是狀態）；
四步走完的收尾訊息（原 `--primary` 底）改 `--success` —— 那正是 `.mcp-bar.on` 的語意。

橘色與 amber 一樣不能借：它們在本示範是「機密」與「對 AI 隱藏／授權窗」，
借過去會稀釋那兩套訊號（同 App v3.7.1 給 Beta 標籤選中性色的理由，[APP快照](../refer/APP快照.md)）。
