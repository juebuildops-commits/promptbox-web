## 0. 為什麼本 PRD 現在是「暫緩」而不是「進行中」

官網要先出去（比賽曝光 + 釋出 Free 版），而且**產品即將改名**（商標問題）。
在這兩件事落定之前開始做本階段，會踩到三個不可逆的坑：

| 坑 | 說明 |
| :--- | :--- |
| `iss` 欄位帶著舊名字 | [ADR-008](../appsync/ADR-008_授權憑證格式與離線驗證契約.md) 的憑證 payload 有 `"iss": "promptbox.app"`。憑證**不可撤銷**（B2）—— 改名前簽出去的每一張，都會永遠帶著舊網域 |
| 網域買錯 | 現在買 = 買一個要丟掉的東西，還會留下要 301 的舊網址。目前沒有任何網址被索引，這個乾淨的起點不該浪費 |
| Polar 商品與寄件身分 | 商品名稱、Merchant of Record 的顯示名、Buttondown 寄件網域，全部帶名字 |

**因此本 PRD 的定位是：規格寫清楚、暫不動工、解凍條件明確。**

## 2. 功能需求

### FR-28　Polar 商品 + Webhook 端點（D9 / D10 / D22）
商品定義與處理順序見 [接縫文件 §4](../appsync/官網金流與授權發放接縫.md)。兩條硬性紅線：
* 🔴 **驗 webhook 簽章不可跳過**：沒驗簽的端點 ＝ 一個公開無認證的簽發器，任何人 POST 一段 JSON 就能拿到合法的永久授權。
* 🔴 **冪等不可省**：webhook 會重送。沒有冪等表，一次重送就是多簽一份永久有效、無法撤銷的憑證。冪等鍵用 event id，不是 order id。
* **Polar 的 license key 功能不使用**（D10）：它的 `validate` / `activate` API 永不由 App 呼叫。

### FR-25B　Supabase 資料表（正式金流與簽發帳本）
三張表，定義見 [接縫文件 §5](../appsync/官網金流與授權發放接縫.md)：

| 表 | 性質 |
| :--- | :--- |
| `entitlements_issued` | 🔴 **只增不改**。這是「我簽過什麼」的帳本，完整存下 `jws` 字串 |
| `update_rights` | **可以改**。記錄 Pro 更新權到期日，退款與續訂都改這裡 |
| `webhook_events` | 冪等鍵紀錄 |

### FR-29　Pro 下載閘門（D18）
* **承接階段五下載代理層**：基於 [階段五 FR-27C](./PRD_階段五_會員與帳號中心.md) 所建立的 `/dl/` 代理架構，擴充 Pro 版本端點（`/dl/pro/:platform`）或授權校驗邏輯：
  * 登入者請求 Pro 下載連結時，伺服器先校驗其 `update_rights`：
    * **更新權有效（或永久更新權）**：發放具短時效之簽名下載 URL，並 302 導向 R2 對應安裝檔。
    * **更新權已到期**：導向使用者最後合法擁有版本之下載，或引導續訂更新權以取得新版。

## 3. 接縫細節與缺口處置

### 3.1 商業授權席次指派（D23：買 4 送 1）
結帳時只有購買者一個信箱，簽發必須走非同步模式：
```
webhook → 建立 5 個【pending 席次】（只記數量與訂單，不簽）
                ↓
購買者登入帳號頁 → 逐一填入席次 email
                ↓
每填一個 → 簽一張 → 寫帳本 → 寄出
```
🔴 一旦簽出就不能改指派對象（不可撤銷），因此填寫 email 的介面必須有二次輸入確認。

### 3.2 改 Email 出口處理
憑證綁 email（D12）且不可撤銷。顧客換信箱或打錯字時，唯一的解是**對正確信箱補簽一份**：
* `entitlements_issued` 允許同一 `order_ref` 有多筆，加 `supersedes` 欄位標註前一筆。

## 5. 驗收條件

| # | 條件 |
| :--- | :--- |
| **AC-30** | 一筆真實付款 → 憑證自動簽出 → App 內離線啟用成功，全程無人工介入 |
| **AC-31** | webhook 重放 10 次 ⇒ `entitlements_issued` 仍只有 1 筆 |
| **AC-32** | 🔴 更新權到期 ⇒ 下載頁拿不到新版；同一台機器上已安裝的版本行為完全不變 |
| **AC-33** | 商業授權買 4 席 ⇒ 產生 5 個 pending 席次，逐一指派後各簽一張、各綁各自 email |
| **AC-34** | 私鑰未設定時，簽發端點回可辨識錯誤且不簽出任何東西 |
| **AC-35** | 退款 ⇒ 更新權撤銷、憑證不動；使用者保有當下版本 |
